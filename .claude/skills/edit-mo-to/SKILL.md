# edit-mo-to

The user's own editing workflow. You run it in the main conversation and own all talk with the user. Agents do the heavy, self-contained work: `ugc`, `broll`, `claymation`, `pixar`, `product-ad` (style), `motion-designer` (new looks and templates only), `editor` (builds CapCut, renders overlays), `qa` (checks).

**Before step 1:**
- Resolve `{root}`, `{python}`, `{tmp}`, `{capcut_drafts}` from `.claude/edit-mo-to/machine.json` (see CLAUDE.md) and pass resolved paths to agents.
- Read `{root}/.claude/edit-mo-to/preferences.md` (General) and `my-preferences.md` if it exists (the editor's own rules; it wins on conflict), then `clients/<client>.md` once you know the client, and `reference/steps.md` (gate wording, dispatch templates).

## Hard rules
- **STOP at every ⛔ gate.** Ask and wait; never assume a choice the process says to ask about. A gate the user already answered (in the brief message or earlier: folder, B-roll source, generator, music, VO file) is answered: confirm it in the job card and go on. Ask the remaining questions of a step together, not one per message.
- **Work in parallel where nothing depends on order:** independent agent runs (prompts agent per timeline, QA per timeline, `motion-designer` while prompts are written) go out in one message. Never parallel two `editor` runs on one project, or anything across a ⛔ gate.
- **The brief is law.** Every brief rule goes on the checklist, and QA checks it.
- CLAUDE.md's formats apply (chat tables, `seconds:frames`, full paths, 9:16, user exports). **Never add captions before step 10,** except the `TEMP_EN_delete_me` review track; at step 10 the editor chooses. Prompts go in copyable code blocks.
- **Keep agent output small.** Agents hand back ~20–30 lines and leave full tables, prompts and plan JSON in `{tmp}/reports/<job>/`. Pass those paths on (style agent → editor and QA) instead of the content, and show the user the deliverable table from the file without re-summarising: `plan_table.txt` for plans; for prompts, paste `prompts.txt` in chat (every prompt in full, each in its own code block, lock lines in full).
- **Every dispatch passes paths, not content:** `pack` (`{tmp}/reports/<job>/pack_<style>.md`), `inventory` (`{tmp}/reports/<job>/inv/inventory.json`, when client B-roll exists), `timings` (the `media_timing.py vo` JSON file) and `timings_compact` (the `--compact` text), and `limits` (`{tmp}/reports/<job>/limits.json`). Templates in `reference/steps.md`.
- **Re-runs post only what changed:** only the changed sentences of a fixed prompt (or the prompt file path), not the whole prompt and its locks. After a small fix run `qa` with `scope: delta` and `changed:`; a full QA run is for the first pass at each gate, or when QA says the change reaches further.
- **Job card:** keep a running card (client, product, style, video folder, brief checklist, script, script language, VO path + timings, B-roll source, generator, music, project name, timelines, and from the first build of a TEMP_EN job "TEMP_EN on: delete before export", then "TEMP_EN still on: <timelines>" once the editor has deleted it from some timelines, and "TEMP_EN removed" when it is gone from every timeline). Re-show it when it changes.
- **Language:** reply in the editor's language (English, Taglish or Tagalog). Never translate the script, the VO, the generator prompts or the editor's text. Judge the editor's language only from their own words to you: their chat messages and the brief they send (a brief written in Tagalog or Taglish counts). Never from the video's own text: the script and the editor's script edits, the VO, prompts, captions or on-screen text, which can be Tagalog while the editor talks to you in English.
- **Model pick:** When you choose the model yourself (proposing a default, or generating for the editor), use `generators.py pick` / the editor's default and never a model in their avoid list. Run `.claude/edit-mo-to/run tools/generators.py pick [--site <site>]`: it prints `<site>:<model>` from this computer's Settings ("When Claude picks, never use" and "Claude's default model"; none set: the site's first model). In the model question, still list every model and set its `default` to that model (the part after `:`). Exit 1 means every model is avoided, and exit 3 means it can't read the editor's model settings: in both cases ask the editor which model, never guess. The editor may choose any model, avoided or not.
- **Temporary English (TEMP_EN):** on when the script's language is not English or Filipino (Tagalog and Taglish count as Filipino). Every build then carries a top-of-frame text track `TEMP_EN_delete_me` with a literal English line per script line, so the editor and QA can follow the meaning. The editor deletes it before export. A plain English or Filipino job has no TEMP_EN and no extra question.

## The 12 steps
1. ⛔ **Brief.** Ask for the brief (PDF, docx, Notion URL or pasted), reference videos, and the per-video folder under `{root}/`. If they came with the request, just confirm the folder exists and go on.
2. **Study the brief** (steps.md covers PDF, docx, Notion and video).
   - Build the **brief checklist**: every rule quoted with its source (length, ratio, tone, hook/CTA rules, must-show / never-show, claims, music and SFX, text style, export settings, deadline).
   - Study the reference videos (frames + transcript) and pick the style.
   - Read the **client** and **product** from the brief and put them on the job card. A brief that names neither leaves them off the card (don't ask just for a name).
   - Note the **script language** on the job card (the brief's script, or the language the brief asks for; ISO code such as `es`, `de`, `en`; a Filipino, Tagalog or Taglish script is noted as Filipino and keeps `--lang en` for timings). Not English and not Filipino: TEMP_EN is on (Hard rules).
   - If the user or brief wants a reference's graphic look and `motion\CATALOGUE.md` has no match, dispatch `motion-designer` with the reference and a few client-footage frames. Its style spec and templates feed the style agent's plan.
   - **Questions about the brief:** while building the checklist, mark every rule that is unclear, implied ("premium", "like the reference"), conflicting (with another rule, or with the editor's preferences: the brief wins until the editor answers) or missing (the brief is silent on length, ratio, music, CTA or on-screen text). Ask them at the gate below, after the checklist table, in the same message: at most 6, numbered, most important first, each with one line on what the answer changes. Each answer becomes a checklist row with source `editor, <date>` that QA checks like any brief rule (not saved to client notes). A question the editor skips: say the default you'll use and add it as a row with source `assumed, <date>`. A clear brief: "No questions about the brief."
   - ⛔ Show the checklist and style; ask the user to confirm or add.
   - Once it's confirmed, write `{tmp}/reports/<job>/limits.json` (`<job>` = product name, no spaces) with only the keys the brief or the editor's answers fix: `min_s`, `max_s`, `ratio` (e.g. "9:16"), `fps`, `caption_band_px` (400), `no_text`. The plan check and QA read it: the canvas is the plan's `width`/`height` (default 1080x1920), and `ratio` cross-checks it, so a non-9:16 job (1:1, 4:5, 16:9) also needs that `width`/`height` in `plan2.json` (tell the style agent).
   - **Before step 3, once per job:** write the context pack, `.claude/edit-mo-to/run tools/context_pack.py <style> [--client <client>] [--generator higgsfield|google-flow [--model <model id>]] --out "{tmp}/reports/<job>/pack_<style>.md"` (rewrite it once if the generator or model is only chosen at step 6; otherwise reuse it unchanged, for the style agent and QA). When the client gave B-roll: the inventory, once, `.claude/edit-mo-to/run tools/sheets.py inventory "<folder>" "{tmp}/reports/<job>/inv" --out "{tmp}/reports/<job>/inv/inventory.json"` (it creates the folder); fix rounds reuse it. `<folder>` is the client B-roll folder only when it holds about 60 clips or fewer. A bigger library: list its subfolders, shortlist the ones that fit the script and brief, and run it per shortlisted subfolder into `{tmp}/reports/<job>/inv_<subfolder>/` (or add `--max N`); pass those `inventory.json` paths, and the style agent reads only their sheets. Clips run in parallel and strips are cached by file, so a re-run or a later subfolder costs only the new clips.
3. **Script.**
   - Brief has a script: use it word for word.
   - No script: ⛔ ask your questions, write it, run `qa` (gate `script`), ⛔ wait for approval.
   - **TEMP_EN on:** write a literal English line for each script line and show it in an `English (temporary)` column next to the script in the script table, so the editor can correct it. Save it as `{tmp}/reports/<job>/script_en.txt`, one line per script line, same order and count as `script_file` (one English file per VO file when hooks have their own VO). Apply the editor's corrections to the file.
   - ⛔ **Pick the graphics** (right after the script is approved, whenever the video will have on-screen graphics: the editor wants motion graphics, or you plan overlay cards such as badges, stats, proof cards, CTAs; before "Storyboard first?", so a storyboard already shows the picks and the build uses them: fewer revisions): list the graphic moments (each on its script line), and for each pick 2–4 fitting templates from `motion/CATALOGUE.md` for the style and brief. **Suggested:** read `motion/trends.json` (what's popular on prompt-motion.com, by category, mapped to our templates); among the fitting templates, mark the ones in the most popular fitting category `"suggested": true` with `"why": "Popular on Prompt Motion: <category>"`, list them first, and make one of them your `default` unless the brief or style clearly needs another. Popularity never beats fit: never suggest a template that doesn't suit the moment. Ask them in chat as one table per moment: `template | what it does here | ★ Suggested (why)`, your pick first, plus "Let Claude choose"; each template's preview still is `motion/previews/<template>.jpg` if the editor wants to look. The editor may pick **several** templates for one moment (different styles to compare); the answer is always a list. Keep the answers as `graphics_picks` (`{"<line id>": ["<template>", …]}`; `["auto"]` = your choice): pass them to the storyboard dispatch (its panels show those templates) and to the edit-plan dispatch (step 7), in the client's colours. Several picks: the storyboard shows each as its own variant of that panel, and the build gets one extra **style timeline** per extra pick (timeline 1 uses every moment's first pick, timeline 2 the second picks, and so on; a moment with one pick keeps it in every timeline), so the editor compares them in CapCut and keeps one. **A link instead of a template** (e.g. a prompt-motion.com video): the editor wants **that look** for this moment, so build it: never swap in the "closest" catalogue template, and don't offer that as the suggestion (only if the editor asks for it). The page text alone (a poster and a short prompt) says nothing about the look: download the page's **video** (its `<video>`/`og:video` source) into `{tmp}/ref/`, make frame sheets of it (motion-designer's "Reference study"), and dispatch `motion-designer` with the video, the sheets, the page's prompt and the creator's name (match the look: palette, type, layout, full-frame scenes, motion and pacing; the client's text, and the client's colours unless the editor says to keep the original's). The new template takes that link's place in `graphics_picks`, and its preview card goes in the catalogue. Say in chat whose look it is (credit the creator) and that an exact copy of someone's design in a paid client video needs their okay. A page you can't read: ask the editor to paste the prompt. A plain video with no graphics skips this.
   - ⛔ **"Storyboard first?"** Ask once the script is set (yes for new clients, new styles or AI-heavy ads; skip for repeat formats). If yes: ask the B-roll source and generator (and the model, for either site) now (step 6's questions, not asked again later). **Board first, images fill in:**
     1. Dispatch the style agent (`mode: storyboard`, phase `prompts`). It also writes the skeleton `<folder>/storyboard/storyboard.json` (one beat per shot with its shot info and keyframe `prompt`; the character sheet prompts in `characters`). **Paste every image prompt in chat, each in its own code block, never only in a file.** Character first: any character-driven ad (always Pixar / claymation) starts with the **character sheet prompt** (one per recurring character); its beats keep `"prompt": null` until every `CHAR-n.png` is saved. ⛔ Wait: "Generate the character sheet and send it to me / tell me when it's saved."
     2. Then the **storyboard keyframe prompts** (`SB-1…`), written to match the approved character sheet(s) (attach them as references; for a character ad this is a second phase-`prompts` dispatch, which fills each beat's `prompt` in `storyboard.json`). ⛔ Wait: "Generate the keyframes and tell me when they're saved in <folder>/storyboard/."
     3. When the images are saved: dispatch the style agent again (phase `board`) to refine the storyboard from the real images (`storyboard.py`), show the `storyboard.html`, and ⛔ ask "Approve this direction, or tell me what to change?" Never ask for approval of the direction as final while keyframes are missing, unless the editor says to approve it anyway.
     The approved storyboard is the plan for step 6: its shots and graphics carry over, and the keyframes become the AI clips' start frames.
   - TikTok product ad: no script. **Music first:** ⛔ "Suno prompt or your own no-copyright YouTube music?", wait for the track, go to step 5 (beats).
4. ⛔ **Voiceover.** Wait for the user's ElevenLabs file. Note whether it's **one file** (hooks + body) or **one per hook/body**; it sets each timeline's `vo_in`/`vo_out`.
   - **No voiceover:** always offer it with the voiceover question ("or no voiceover: text and music only"). The editor choosing it means a video with no VO: the script lines become **on-screen text** (kinetic type, titles, cards) and the plan has no `vo`. Step 5 then times the video from the **music beats** (`media_timing.py beats <music>`; no music yet: ask the music question now, step 11's, since the cut follows it) or, with no music either, from a reading pace (about 2.5 words a second, at least 1.5 s a line). Say on the job card `VO: none`. Step 10 captions are skipped (the text is already on screen) unless the editor wants them; tell them so at step 10.
   - **Reusing an existing VO** (saves credits): `media_timing.py vo <file>` with no script, show its sentences with times, ⛔ let the user pick the spans. The script becomes those spoken lines; each timeline's `vo_in`/`vo_out` is its span.
5. **Timing.** VO: `media_timing.py vo <vo> <script.txt>` (script lines in a temp txt); show the line timings. Any `matched: false` line is a ⛔ check (mispronounced or changed words). Music (product ads): `media_timing.py beats <music>`.
   - **Script language:** every `media_timing.py vo` and `speech_cuts.py propose` call takes `--lang <xx>`: a script that is not English or Filipino passes its own code (e.g. `--lang es`, so the multilingual model hears it and accented words match); English and Filipino (Tagalog, Taglish) scripts keep `--lang en`, the default. An unknown code is refused.
   - Save both forms once: the JSON to `{tmp}/reports/<job>/timings.json` (`timings`, for the tools) and `media_timing.py vo <vo> <script.txt> --lang <xx> --compact` to `{tmp}/reports/<job>/timings.txt` (`timings_compact`, for agents to read; it reuses the cached transcript). Keep the script txt as `script_file`.
   - **Talking-head A-roll with its own audio** (avatar, creator, host recording): clean it first. `speech_cuts.py propose <clip> --out {tmp}/cuts/<name>.cuts.json` (reuses the cached transcript) finds dead air (pauses over 0.55s trimmed to a breath; edges snapped to real silence) and stutters / false starts / retakes. Silence cuts apply automatically. ⛔ Show the mistakes as a table (`id | type | cut | removes | keeps | recommend`) and ask which to cut; emphasis ("never, never") looks like a stutter. Then `speech_cuts.py apply <cuts.json> --approve <ids> --reject <ids> --script <script.txt>`. Its `keep.json` (`segs`, re-timed `words` and `lines`) replaces the VO timings for that clip and goes to the style agent as `aroll_cuts`. Tighter pacing: `--gap 0.3 --breath 0.15`.
6. **B-roll and prompts.**
   - ⛔ "Use the client's B-roll, generate AI video, or both?" If AI: ⛔ "Where will you generate: Higgsfield or Google Flow?" Then ⛔ "Which Higgsfield model?" or ⛔ "Which Google Flow model?" (the chosen site's models in `.claude/edit-mo-to/generators.json`, plus "Other": then ask the model's name in chat and pass it as `generator_model`). The card shows `generator=Higgsfield · <model label>` or `generator=Google Flow · <model label>`; a Google Flow job with no model (every old one) shows `Google Flow` and keeps Flow's own limits; an old card's `Seedance` reads as Higgsfield · Seedance 2.0. The limits come from `generators.json`; when `plan_tools.py` prints a `warning:` line (limits not verified, or a model not in the table, which gets the table's strictest limits for Higgsfield, or Google Flow's own limits for Flow), say so in chat. It is not an error.
   - Dispatch the style agent (`mode: prompts`): one per timeline or ad, all in one message, each with its own `job` (e.g. `<Product>_T02`) so their files don't overwrite each other. Each runs `plan_tools.py prompts` + `check-prompts` until clean. Then `qa` (gate `prompts`), one per timeline in one message: it runs `qa_check.py prompts` first and judges only meaning and brief rows.
   - Show the table and prompts (paste `prompts.txt`). Fix QA FAILs by re-dispatching (then delta `qa` on the fixed rows), or list unresolved ones for the user.
7. ⛔ **Gather and build.**
   - If AI clips are needed, wait until the user says where they are, then QC the batch with `qc_clips.py run <clips folder> <expected.json>` (write `expected.json` from the prompts table: name, length, keywords, product/phone, use span). It checks length, size, baked-in text, product and phone visibility, and prints PASS/FLAG per clip; open the contact sheets of FLAG clips only, and ⛔ ask the user to regenerate real failures.
   - **Graphics picks:** the edit plan uses the templates the editor picked in step 3 ("Pick the graphics"): pass them as `graphics_picks`. Don't ask again; ask only about graphic moments that are new since (a script line changed or was added), the same way.
   - Dispatch the style agent (`mode: edit-plan`): one per ad (project), all in one message; never one per timeline, because a project's `plan2.json` shares blocks (the body) across its timelines and the build and `qa_check` take that one plan. Plan `overlays` use `motion\CATALOGUE.md` templates and the **editor renders them** during the build; only a graphic no template covers needs `motion-designer` first. Keep the plan's `music` null (except product ads): music goes in at step 11, and `qa_check` FAILs a planned music track the build doesn't have.
   - **TEMP_EN on:** the dispatch passes `script_lang`, `script_en` (`{tmp}/reports/<job>/script_en.txt`) and `timings`; the style agent writes `"temp_en": {"english": "<script_en.txt>", "timings": "<timings.json>"}` in `plan2.json` (a timeline with its own VO gets its own `temp_en` with that VO's English file and timings, or `"temp_en": null`; `plan_tools.py check` errors otherwise). The build then adds the `TEMP_EN_delete_me` track to every timeline, above every other text track. Put "TEMP_EN on: delete before export" on the job card from this first build. Removal is per timeline: a timeline the editor cleared gets `"temp_en_removed": true` in its `plan2.json` timeline (a new timeline revised from it copies the flag), so no later build of it adds the track back; the plan-wide `"temp_en_removed": true` (dispatch `temp_en_removed: true`) only when every timeline is clear or the editor says so.
   - Then, in this order:
     1. `.claude/edit-mo-to/run tools/plan_tools.py check "{tmp}/reports/<job>/plan.json" --limits "{tmp}/reports/<job>/limits.json"`. Don't go on while it prints errors: send them back to the style agent.
     2. Dispatch `editor` (`action: build`, project name = product name, hooks as timelines, the plan path, `import_files` = every file the user gave for this video). It builds the whole project in one `build_project.py build` call, imports the files into the media panel, builds from the originals and writes the clip sheets. If the project name is taken, ⛔ ask for another (e.g. "<Product> 2").
     3. `.claude/edit-mo-to/run tools/qa_check.py build "{tmp}/reports/<job>/plan.json" "{capcut_drafts}/<Product>" --limits "{tmp}/reports/<job>/limits.json" --search "<client folder>" --out "{tmp}/reports/<job>/qa_check.json"` (the mechanical checks, no eyes; `--out` writes the JSON there and prints the verdict).
     4. Run `qa` (gate `build`, one per timeline in one message) with `qa_check` = that file: it judges only the sheets and the brief rows.
     5. Fixes: the style agent edits `plan2.json` rows and re-expands, `check` again, the editor applies them as `revise-in-place` (patch ops; `old_plan` = the built plan copy `<base>/.edit-mo-to/built/<timeline>.plan.json`, `new_plan` = the re-expanded `plan.json`), then `qa_check.py build … --changed <#s>` and a delta `qa`.
   - Show the editor's report and QA verdict. Send the user to CapCut only once QA passes, or with the remaining issues listed.
8. **Transitions and effects** are in the edit plan where they fit the style and brief: few and subtle (3–5 of ≤0.3 s at section changes), each with a whoosh. To add them to a built timeline, the editor uses `capcut_project.py patch` op `transition` (copies a cached CapCut effect from a past project).
9. ⛔ **Review loop.** The user reviews in CapCut and edits it themselves or gives changes. For each change, ⛔ ask which timeline, and new timeline or in place (in place makes a backup), and ⛔ ask them to quit CapCut completely (it rewrites projects on close and would drop our change; the tool refuses while CapCut.exe runs).
   - Ask "quit CapCut" once per review round, before that round's first write, not before every write.
   - The hand-edit diff runs before any write (`edit_diff.py diff --last`, by the editor), so the user's edits are reported and logged, never lost.
   - **TEMP_EN removed:** when the editor's report says the `TEMP_EN_delete_me` track is gone from a timeline, or the user says they deleted it there, add `"temp_en_removed": true` to that timeline in `plan2.json`, re-expand, and set the job card to "TEMP_EN still on: <the other timelines>". Only when every timeline is clear (or the editor says it is gone everywhere) set the plan-wide `"temp_en_removed": true` and "TEMP_EN removed". Its deletion is never a hand edit to learn from (`edit_diff` ignores that track).
   - Then: style agent (`edit-plan` + `revision`), `plan_tools.py check`, `editor` (`revise-new-timeline` | `revise-in-place`; in place passes `old_plan` (the built plan copy, never the re-expanded `plan.json`) and `new_plan`, and small timing, swap and scale changes become `patch` ops, not a rebuild), `qa_check.py build` + `qa` (`build`, delta with `--changed` for small changes). After `revise-new-timeline`, `plan.json` still names the old timeline: run `qa_check.py build` (and later `add-music`) on the new timeline's built plan copy `<base>/.edit-mo-to/built/<new name>.plan.json`; `qa_check` stops on a `--timelines` name the plan doesn't have.
   - **Overlay tweaks** ("move the card up") stay in the main conversation: change the vars, re-render with `motion_render.py`, preview, then have the editor swap the files. No agent for small tweaks.
   - Repeat until the user is happy.
10. ⛔ **Captions.** Ask: "Captions: will you run CapCut auto-caption yourself, or should I add them? (Mine are simple text captions with the script's exact words and a pop-in; no word-by-word animation. For an animated look, use CapCut's caption presets.)"
    - **They run auto-caption** (as before): wait until they say it's done.
    - **I add them:** in the same message ask which timeline(s) and to quit CapCut, and wait for both. Then `editor` `action: add-captions` (per timeline: the hand-edit diff first, then `build_project.py captions` with `--script` and `--timings` of that timeline's VO, then `qa_check.py captions`). The captions are text chunks of the script's exact words timed to the VO, following the timeline as it is now (trimmed or cut VO is followed; words of a cut stretch are dropped and listed), in the look from the pack's Captions section and the plan's `captions_style`. Show the `qa_check captions` FAIL and OPEN rows; run `qa` (gate `captions`) when a FAIL needs judging or the brief has caption rules. A timeline that already has a `captions` track is refused: the user deletes that track in CapCut first.
    - From here on use `qa_check.py captions`, never `qa_check.py build` (it FAILs any caption track).
11. ⛔ **Music** (non-product-ad styles): "Suno prompt from me, or no-copyright YouTube music?"
    - Suno: write the prompt; max 18s, so split into parts with crossfade notes.
    - When the file arrives: ⛔ ask which timeline(s) and to quit CapCut, then `editor` `action: add-music`. It **merges** the music (about −20 dB under the VO), keeping captions and hand edits, with a backup.
    - The editor builds a music-only draft (`build_project.py music`) and merges it with `add-tracks`. Only now does the project get music; until step 11 the plan's `music` stays null.
12. **Export** is the user's. On a TEMP_EN job, first run `capcut_project.py segments "<project>" "<timeline>"` on every timeline (fresh, not the job card); when any still has `TEMP_EN_delete_me`, the hand-off's first line is "Delete the TEMP_EN_delete_me track before export" with those timelines named. Then run the **learning step** (`reference/learning.md`), unless the editor skips it (by saying so): then propose and save nothing, mark `export` done, and say the video is finished.

## Tools
- Run every tool as `.claude/edit-mo-to/run tools/<name>.py …`. Bash runs from `{root}`: no `cd`, no env-var prefix and no Python path in front, so the project allow rule `Bash(.claude/edit-mo-to/run *)` matches and nothing stops for permission (`run` picks the tools `.venv` Python and sets `PYTHONIOENCODING=utf-8`). Pass the same form on to agents. Tools in `{root}/.claude/edit-mo-to/tools/`:
  - `media_timing.py`: `vo <audio> [script.txt] [--lang xx] [--compact]` (`--lang` default `en`; other languages use the multilingual model), `beats <audio>`
  - `captions.py`: `chunks <vo.json> <script.txt> <project> "<timeline>" [--max-words 4] [--vo-track NAME] --out f` (caption chunks timed through the timeline's VO segments), `temp-en <vo.json> <script_en.txt> --out f` (the temporary English rows); the build and `build_project.py captions` call them for you
  - `context_pack.py <style> [--client c] [--generator g [--model m]] --out pack.md`: the rules one dispatch needs (step 2, once per job)
  - `generators.py pick [--site <site>]`: the model Claude uses when it chooses one itself (never one in the editor's avoid list)
  - `sheets.py`: `inventory <folder> <out_dir> [--max N] [--out inventory.json]` (client B-roll catalogue, once per job; shortlisted subfolders of a big library), `clips <plan> "<timeline>" <out_dir> [--ai]`, `overlays <plan> "<timeline>" <out_dir>` (frame sheets for QA)
