# Edit Mo To GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local companion web GUI ("Edit Mo To by Joshua Calonge") that shows every `/edit-mo-to` step and gate from on-disk job state and carries the editor's answers back to the running Claude Code session.

**Architecture:** Claude writes `<video>/.edit-mo-to/job.json` through `gui/job.py`; the GUI server (`gui/server.py`, stdlib `http.server` on `127.0.0.1`) renders it and appends the editor's answers to `inbox.jsonl`; `gui/wait.py`, run by Claude in the background at a gate, exits when an answer arrives and so wakes Claude. A launcher `.claude/edit-mo-to/run` runs only the workflow's own scripts so one project allowlist rule covers them on every machine.

**Tech Stack:** Python 3.12 standard library (no new required package), plain HTML/CSS/ES-module JavaScript (no build), pytest, POSIX `sh` (Git Bash on Windows).

**Spec:** `docs/superpowers/specs/2026-10-27-gui-design.md` (read it first; it is the source of truth for every page, dialog and rule below).

## Global Constraints

- The 12 steps, their order, gates and gate wording stay; only the storyboard order changes (spec "Changes to the existing workflow").
- Server binds `127.0.0.1` only; per-launch token; no login screen; reads/writes only inside `{root}` and `{tmp}`.
- One writer per file: `job.json` = `gui/job.py` (plus the server's `create_job` for a brand-new folder only), `inbox.jsonl` = server, `gui.json` = server.
- The server never writes a CapCut project and never runs a workflow tool that changes files; it runs only the read-only checks listed in the spec.
- A step shows `done` only after Claude records it; nothing is shown as done, saved or listening unless verified.
- Branding: "Edit Mo To", "by Joshua Calonge", gold "JC" emblem; no other name anywhere; no name setting.
- Verse at the bottom of the sidebar on every page: *"Remember the Lord your God, for it is he who gives you the ability to produce wealth."* and "DEUTERONOMY 8:18".
- Obsidian Champagne tokens exactly: `--bg #0C0B0A --panel #151311 --panel2 #1D1A17 --line #2A2622 --line2 #3A342D --text #F3EFE8 --muted #A69D91 --dim #6F675D --accent #D4AF6A --on-accent #1A1408 --ok #7DCB9C --wait #93B5E3 --err #EE7B6E --opt #BBA6E0` (soft = 12% alpha).
- Times shown in `seconds:frames` at 30 fps (`media_timing.to_sf`).
- Windows and macOS; paths via `tools/machine.py`; no machine paths in tracked files.
- Never commit `my-preferences.md`, `clients/`, `edit-patterns.jsonl`, `_practice/`, `machine.json`, `feedback.jsonl`, video folders.
- Tests run from `.claude/edit-mo-to/tools/`: `.venv/Scripts/python -m pytest tests -q` (Windows) or `.venv/bin/python -m pytest tests -q` (Mac). Below, `PY` means that interpreter.

## Review Focus

1. **Editor answers while Claude isn't listening** (gate open, no `wait.py`): the event must stay in the inbox, the GUI must say "Claude isn't listening…", and the next `wait.py --after N` must return it immediately. → test in Task 4.
2. **Two answers for one gate** (GUI and chat, or a double click): Claude must see both, the second one for a closed gate flagged `stale`. → test in Task 2.
3. **Paths with spaces and non-ASCII** (`D:/Video Editing/Uvola Cereza Ácida`): every API, upload and `run` call must work with them. → tests in Tasks 1, 2, 5, 6.
4. **A keyframe saved from outside the app while the page is open:** the card must update on the next poll without a reload. → test in Task 6 (API reports it); manual check in Task 10.
5. **Server already running on the port from an older version or another program:** the launcher must reuse ours only when `/api/ping` says `edit-mo-to-gui` with the same `version`, otherwise restart ours or pick the next port. → test in Task 7.
